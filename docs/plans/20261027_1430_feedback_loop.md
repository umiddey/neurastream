# Continuous feedback: every script reports in, a watcher pings you within minutes, and the alarms grade themselves
Worktree: /home/ukd/Work/neurastream-feedback-loop
Branch: feat/feedback-loop
Summary: Every scheduled neurastream job writes a heartbeat. A small timer checks the heartbeats, failed services and the incident detectors every few minutes, even when no Main session is open. Each new problem pings you on Discord and opens an incident. The weekly report also counts silent failures, guards that blocked harmless work, and alarms you keep dismissing.

## Goal
- Owner (2026-10-27 ~14:25), after wip-snapshot/wip-backup failed for six days unnoticed: "do we have continuous feedback in neurastream? how could we have automatically found out the problem with our scripts? … even with that, do we have continuous feedback? are we getting there? are we building there?" Main answered: partly, all checks are pull-based (Main's prompt, main-start, weekly report). Owner then said: "write it".
- Done =
  1. Every scheduled job (wip-snapshot, wip-backup, pages, the page server, metrics report, the watcher itself) writes a heartbeat `{name, at, ok, detail}` on success AND on crash.
  2. `neurastream watch` (one shot, run by a timer every `watch.interval_min`, default 5) finds:
     - failed heartbeats;
     - stale heartbeats (older than the per-job `watch.expect` window);
     - failed neurastream systemd/launchd units;
     - the D1/D3 detector findings;
     - and it does all of this with no Main session open.
  3. Each NEW incident from the watcher posts ONE notify message (Discord/Slack). There is no repeat while the same incident stays open.
  4. A guard block followed by the same action reworded and allowed opens a "possible guard false positive" incident.
  5. The weekly report shows silent failures, suspected false blocks and, per detector kind, how many of its incidents were dismissed. A detector with a high dismiss rate becomes one "noisy detector" incident.
  6. `main-start` says when the watcher itself has not run (who watches the watcher).
  7. Live proof on this PC: a forced failure reaches Discord within one interval.

## Forbidden
- Host-neutral: src/core names no harness (omp/opencode/codex/claude/cursor); docs/adapter.md. Unit/agent install goes through the same service-manager seam as `wip on` / the page setup; inject it in tests.
- Never post the same open incident twice. One message per new incident (dedup by fingerprint via `addIncident(...).deduped`). Rate cap is `watch.max_posts_per_run` (default 3); the rest go into one summary line.
- Notify text never contains secrets, file contents or env values: only the job name, the time and the first error line, cut to 200 chars.
- The watcher never edits plans, indexes, guard files or blockers, and never restarts a service. It reports.
- A heartbeat write failure must never fail the job itself (log and go on). A watcher crash writes its own failed heartbeat.
- Tests never touch the real home, network, Discord, systemd or launchd: inject the clock, the notifier, the unit lister and the service manager.
- Work only in /home/ukd/Work/neurastream-feedback-loop on feat/feedback-loop. Never push, tag, publish or install (Main does). Commit files by name; never `git add -A`/`.`; never `--no-verify`.
