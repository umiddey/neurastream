# Live re-check: every hold and every "done" carries the command that proves it
Worktree: /home/ukd/Work/neurastream-live-recheck
Branch: feat/live-recheck
Summary: A "waiting on you" card or a "done" claim only shows while its own command still proves it; stale ones are pulled and reported, so I never ask you for something already fixed.

## Goal
- Owner (2026-10-27 ~09:00), after Main asked him for a Gateforge "go" that Gateforge 0.18.0 had already shipped, and after an agent claimed "PM suite is done" while 666 obligations were blocking: "yes, do the live recheck plan please."
- Done = (1) a `WAITING on owner:` line may carry `— still true if: \`<cmd>\`` (exit 0 = the hold is still real); neurastream runs it before a question card is shown, at main-start and after `neurastream metrics ci`; on non-zero it hides the card, opens an incident "stale hold" naming the plan, and prints it. (2) A plan phase or Progress entry claiming done/complete/"nothing left" must be backed: `queue-check` fails a plan with `Status: complete` whose `## Done check` exits non-zero (already true in queue-close) and fails a Progress entry with the words "done"/"complete"/"nothing left" for a phase whose `verify:` command was not quoted with its result in that entry. (3) The rollover handoff note stores each number with `(from: \`<cmd>\`)`; the new session's start prompt lists those commands and says "re-run before repeating any number".
