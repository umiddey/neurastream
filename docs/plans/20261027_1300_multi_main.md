# Several Mains, one queue, never the same plan twice
Worktree: /home/ukd/Work/neurastream-multi-main
Branch: feat/multi-main
Summary: You can run two or more Mains at once. Each one takes plans from the queue and holds them, and no other Main can touch a held plan. A dead Main lets go after 30 minutes.

## Goal
- Owner (2026-10-27 ~12:10): "sometimes I might want more than one main … they are orchestrating different plans and never touching the plans that the other main is doing". ~12:30: "The most important thing is to know for a fact that the plan is being worked on and at the time it's being worked on nobody interrupts it. Nobody else does the same work … this is open source … ensure it's done properly." On "a dead Main frees its plan after 30 min": "the correct way".
- Worker: **deepseek only** (owner ~12:30: "deepseek has to be the model that does it for these two features").
- This plan is the base for the team queue (plan 20261027_1305_team_queue.md). Claims therefore go through a `ClaimStore` interface, which has a local file store here and a server store there.
- Done = (1) `neurastream main --name <id>` starts a named Main; plain `neurastream main` is named `main`. (2) A plan is worked only by the Main that holds its claim, enforced by the guards and not by trust. (3) Two Mains racing for one plan → exactly one wins, every time. (4) A claim with no heartbeat for 30 min is free. (5) The owner sees who holds what in the queue summary and on the phone page. (6) Owner messages can go to one Main (`@id …`) or to all of them.

## Forbidden
- No claim without an atomic primitive. Use `open(O_CREAT|O_EXCL)` / `link()` on the claim file, or a SQLite transaction. Never check-then-write.
- Never free another Main's live claim; only expiry (30 min without heartbeat, `queue.claim_ttl_min`, default 30) or `neurastream claim release <plan> --force` by the owner frees it. `--force` is refused for agents (guard), like the unlock.
- Host-neutral core: claims, leases and stores live in src/core. Only the heartbeat timer and the hook wiring live in src/adapters/omp.
- Tests never use the real home or real time. Inject the clock, use temp state dirs, and run the race test with real separate processes (`Bun.spawn`).
