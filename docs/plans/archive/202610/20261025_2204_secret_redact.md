  - `redactSecrets(text, known): { text, hits: {type, count}[] }`. Replaces each hit with `[REDACTED:<type>]`; the value never appears in the return, the hits, or any log.
  - Shape rules (gitleaks-style, each with a type name): npm `npm_[A-Za-z0-9]{36}`, GitHub `gh[pousr]_…` / `github_pat_…`, GitLab `glpat-…`, OpenAI/Anthropic/OpenRouter `sk-…` (incl. `sk-ant-`, `sk-or-`), AWS `AKIA…` + the value after `aws_secret_access_key`, Google `AIza…`, Slack `xox[abpr]-…`, Discord webhook `discord(app)?.com/api/webhooks/<id>/<token>`, Stripe `[rs]k_(live|test)_…`, JWT `eyJ….eyJ….…`, PEM `-----BEGIN … PRIVATE KEY-----` blocks, URL credentials `scheme://user:pass@`, `.npmrc` `_authToken=…`, generic `(password|passwd|secret|token|api[_-]?key|access[_-]?key|client[_-]?secret)\s*[:=]\s*<value ≥ 8 chars>` (keeps the key name, redacts the value).
  - Known values: `loadKnownSecrets(cfg)` collects exact values (length ≥ 8) from (a) env vars whose name matches `KEY|TOKEN|SECRET|PASSWORD|PASS|AUTH|CREDENTIAL|WEBHOOK` (case-insensitive), (b) `_authToken`/`_password` lines of `~/.npmrc`, (c) `KEY=value` lines of the files in config `secrets.known_value_files` (default: `~/.npmrc` plus every top-level `.env*` in the repos under `paths.work_roots`), (d) the notify webhook secret files. A known value is redacted wherever it appears, whatever the file is named. Cached per process, re-read when a file's mtime changes.
  - Config (`src/core/config.ts`, `templates/config.yml`, README): `secrets.redact` (default true), `secrets.known_value_files` (list), `secrets.extra_patterns` (list of `{type, regex}`), `secrets.proxy` (`none` | `secretgate`, default `none`).

## Background
- omp's `tool_result` hook can replace the content (index.ts already returns `{ content: [...] }` there), so redaction before model/chat/log is possible in-process.
- Open source checked: secretgate (proxy, any agent, ~170 regexes + known values); honmoon, redact-hook, claude-code-redaction-hooks (Claude Code hooks only). None hooks omp, so (1) is built here; secretgate covers the wire.
- secretgate alone is not enough: it cleans only what leaves the machine; the chat screen and local session logs would still hold the secret.
