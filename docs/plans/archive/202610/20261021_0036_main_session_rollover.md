## Goal
- Owner (2026-10-21 00:3x): "after a single sesions grows over 10mb, a new session shoudl automatically start wiht the previous session handing over with the hand off". Then: "okay first plan for this too".
- When done: once the Main session file is ≥ `rollover.max_session_mb` (default 10), Main is told to write its handoff note. At the first owner message after the note exists and no async job or subagent is running, the message is turned into `/main-rollover <message>`; that command opens a new session (parent = old file) and sends the handoff (generated queue/agent state + Main's note) followed by the owner's message. `/main-rollover` also works by hand.
- Limit (omp 18.11.1, Main read the source): event hooks cannot start sessions (`newSession` exists only on the command context, extensibility/extensions/types.ts:785-818, "hooks must not call … to avoid deadlocking the agent loop"), and `pi.sendUserMessage` skips command handling (session/agent-session.ts:9037-9047). The only hook path into a command is the owner's own submitted message (input handlers run before slash parsing, modes/controllers/input-controller.ts:1011-1023). So the switch happens on the owner's next message, never silently overnight.
