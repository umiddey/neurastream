## Background
P1 spec — `agent-score validate <Agent> --plan <plan.md> --phase <P> --evidence <report.md> --section "<heading prefix>" [--weight N] [--note T]`
Records `{type:"validate", agent, plan, phase, weight, weight_src, evidence, section, labels:[...], note}` only when ALL hold; otherwise exit 1 with the reason and nothing recorded:
1. The plan exists and its phase line is ticked `- [x] <P>`; weight = that line's `difficulty: N` via the existing weightFor (`--weight` overrides, as for accept). Unticked → "refused: <P> not ticked in <plan>" (Main ticks after review, so ticking = reviewed).
2. The evidence file exists and has a heading line that starts with the `--section` text followed by end-of-line, space or `(` (e.g. `## CP` matches `## CP (P5, throwaway …)`, not `## CPX`). Section body = lines until the next heading of the same or higher level; it must contain at least one non-blank line.
3. The heavy-run log (config `paths.heavy_log`, existing key) has at least one `END   <Agent> | <label> | exit <n>` line, and at least one of those labels appears verbatim in the section body. Those labels go in `labels`. None → "refused: section cites no heavy-run label run by <Agent>". This ties the report to work the agent actually ran.
4. No earlier `accept` or `validate` event with the same agent+plan+phase → else "refused: already scored".
Board/table: `validate` adds points and counts like `accept` (first-pass unless `--rework`), shown as its own count next to diagnose: header `Accepted (diag/val)`, cell `N (d/v)`. Update the golden board test accordingly. Tests (tests/, temp files only): each refusal above, the heading-prefix boundary, the success record, the board count.
