## Background
- Why a reboot leaves RUNNING rows: omp writes `session_exit` (sessions.ts:166) only on a clean end. A reboot, kernel kill or crash writes nothing, so the ledger infers state from the transcript's mtime alone and shows RUNNING with an idle tag; `liveSubagents` accepts that for 60 minutes (guards.ts:2333-2334).
- Why boot time and not a pid check: the transcript has no pid, and omp keeps no per-session pid file that this repo reads; a session last written before boot time cannot be alive, whatever else is true. A crash without a reboot still leaves a RUNNING row up to the 60-minute bound; a pid-level fix needs omp to record the pid and is a separate plan if the owner hits it.
