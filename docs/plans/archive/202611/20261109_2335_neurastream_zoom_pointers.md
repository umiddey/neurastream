Summary: Every new session starts with a list of everything the owner said in the session before it, one line per message with a short pointer, and `neurastream zoom <pointer>` prints that message word for word along with Main's reply. Nothing is summarised or rewritten; the pointer leads back to the original session file, which neurastream never changes.

- Done = (1) `neurastream zoom` with no argument lists every owner message of the current Main session as `<ref>#<entry id>  <time>  <first 100 chars>`, then `previous session: <file>` when this session started from a handoff. (2) `neurastream zoom <ref>#<id>` prints that owner message word for word, followed by Main's text replies up to the next owner message, then `prev:`/`next:` pointers. Thinking and tool output are never printed. (3) Every rollover handoff, from the launcher or in-process, carries `## Owner's words in the previous session` with that list, so a dropped goal or a later "cancel" is one zoom away. (4) The note request tells Main to end owner-based points with "(said: `<pointer>`)". (5) The output passes through `redactSecrets`. Session files are only ever read.

## Background
Evidence (2026-11-09 23:30-23:35, read-only):
- Session line shape (omp 18.15.0): every entry carries an 8-hex `id`, `parentId` and an ISO `timestamp`. User messages are `{"type":"message","message":{"role":"user","content":[{"type":"text",…}]}}`. omp compaction appends a `compaction` entry and keeps the earlier lines, so the original stays readable after compaction too.
- Under `-projects`, 497 main files; the first 13 uuid characters are unique across all of them (UUIDv7 ms prefix, the same length the `archive` global lists). `01a1c029-5185` matches exactly one file.
- Owner messages per recent Main session (rollover at 5 MB): 13-15, so the handoff list adds about 2 KB. The largest old session (63 MB) had about 304, about 40 KB; handoffs over 100 KB already go to a file (launch.ts:141).
- Session 01a1c029-5185 (2026-11-09) shows the filter at work. Its user messages are the handoff (ownerText → the owner part), 14 owner lines, and one `main-guard:` line, which ownerText drops. Async results and peer messages are `custom_message`, not user messages, so they never enter the list.
- Assistant text parts in that session are at most 1.4 KB. Thinking and toolCall parts are the bulk, and zoom skips them.
- omp exports `PI_SESSION_FILE` to tool commands, which gives "this session" under multi-Main. Only the adapter reads it.

Why pointers, not OptChat's tree:
1. Summary tree + zoom levels (OptChat): rejected. The model sees summaries first, and a summary can drop a goal or keep a revoked rule, which is exactly what happened on Oct 10-14. Every summary line would also be new state to keep correct.
2. Main reads raw jsonl with `read`/`archive`: rejected as the mechanism. The `archive` docs warn it floods context with tool output. It is also omp-only, and nothing ties a handoff fact to an entry.
3. Chosen: a mechanical, complete list of owner messages (prefix previews, nothing selected or rewritten), short pointers, and one read-only command that prints the owner's words plus Main's visible reply. The handoff header already names the previous session file, so pointers chain across rollovers with no new file. The `(said: …)` note convention mirrors the existing `(from: \`cmd\`)` numbers convention, needing only one prompt line and no new code.
- Risk accepted: Main can still ignore the list. The list is in the handoff's first message, the same as the WAITING lines, so it cannot be dropped by a note writer.
- Not covered: words the owner typed in sessions older than the previous one are reached by following `previous session:` one hop at a time. That is enough for "not forget", and a multi-session search stays with `archive.search`.
