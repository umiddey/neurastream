## Background
Evidence (2026-11-07 12:50-12:58, read-only):
- `tailscale ip -4` = 100.109.146.109; `ip -4 addr show tailscale0` holds only that address.
- `ss -ltnp`: pages (pid 271596) listens on 100.109.146.109:7788 (Main restarted it); the owner page (pid 3894) still LISTENs on 100.95.84.100:7787, an address no interface holds. The process is alive, so `Restart=on-failure` never fires: that is the whole bug.
- journal: at boot 09:29 the ui unit failed once (status 127) and systemd restarted it 5 s later, so the on-failure restart loop works on this machine.

Design choice (the three candidates):
1. Bind 0.0.0.0 / tailscale0 — rejected. Bun 1.3.14 `Bun.serve` takes hostname/port/reusePort/ipv6Only only (serve.d.ts:806-844): no SO_BINDTODEVICE, so "tailscale0" means 0.0.0.0. That opens :7787/:7788 on every interface (LAN, docker bridges) and leaves tailnet-only resting on the source-address test `isTailnet` (owner-ui.ts:80-84) + whois alone; README:180 promises "bound to this machine's tailnet address only".
2. In-process re-listen — rejected. Same exposure as today, but each server needs a mutable server holder, `allowedHosts` (owner-ui.ts:1804-1813, cached once) must be invalidated, and the returned `hostname` becomes stale — more code in two files plus the security-relevant ones the Forbidden list keeps closed.
3. Self-exit, systemd restarts — chosen. The service only notices and exits 1; the restart is the unit's existing `Restart=on-failure`, and the fresh process runs today's unchanged start path: bind `tailscale ip -4`, rebuild the Host allowlist, beat. Exposure is identical by construction. No agent command is involved, so startsOwnerUi is untouched; a watcher that ran `systemctl restart` (e.g. inside `neurastream watch`, which agents may run) would be an agent-reachable restart path and is rejected for that reason. Cost: up to 30 s + 5 s RestartSec of downtime per address change; the poll is one `tailscale ip -4` spawnSync (8 s timeout) every 30 s.
- Same-address tailscale restart: no exit; the listener bound to the address survives its removal (pid 3894 above shows that) and serves again when the address returns [INFERENCE: standard Linux behaviour, not tested here].
- ui/pages are systemd-only today (ui-setup.ts / pages-setup.ts:31-32 use systemctl; launchd is used only by watch-setup/wip-setup), so a plain terminal run just exits with the printed line.
