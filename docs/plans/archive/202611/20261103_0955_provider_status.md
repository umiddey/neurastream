## Background
What omp's store means (omp 18.15.0 binary strings + 17.4.1 source; the installed source package is older than the running binary, so semantics were checked in the binary):
- `auth_credentials`: one row per login/key; `disabled_cause` NULL = usable. Set (soft delete) on `/logout` ("deleted by user") or a definitive OAuth refresh failure ("oauth refresh failed: <verbatim error>"). A disabled row never comes back by itself — it needs a new login, so "when is it back" has no answer; the line says `unusable (<reason>)`. `data` = secrets, never read.
- `auth_credential_blocks`: "do not hand this credential out until `blocked_until_ms`" per (credential, `provider_key` = `<provider>:<type>`, `block_scope`), written by `blocks.mark`: (1) a usage-limit/429 hit (`markUsageLimitReached`), until the provider's reset hint or now+60 s (`En`); (2) a usage report showing an exhausted window before the request; (3) a credential invalidated after an auth error (now+60 s, scope `auth`); (4) a transient OAuth refresh failure (now+5 min, scope `auth`). So it is mostly rate/usage limits, sometimes a short auth backoff; the row does not say which, and the plan does not guess — it reports "blocked until T". Rows can outlive their end (omp prunes lazily), hence `blocked_until_ms > now`. omp may also lift a block early when live usage shows room (`healableBlockScopes`); then the row disappears and the next read says ready.
- Scopes seen: zai `credits` (its only scope → whole provider), openai-codex `chat`/`spark`/legacy `shared` (pins use chat models → `chat` treated whole, `spark` partial), cursor `pool:<pool>` (model-dependent → partial), anthropic `tier:fable|mythos` (partial) or `""` (whole), google-antigravity `counter:<key>` (partial), `auth` (whole, short). Unknown future scopes count as whole: a false "blocked" costs a wasted check, a false "free" is today's incident.
- One free credential makes the provider ready: anthropic today has credential 26 blocked until 11-06 21:00 and 25 free; omp switches to the free sibling itself.
- config.yml `enabledProviders` (claude, codex, vscode) lists context-discovery sources, not model providers (binary: `isProviderEnabled(e) = !disabledProviders.has(e)`; the enabled list is the capability registry) — ignored. `disabledProviders` switches a provider off → unusable. models.yml `providers:` adds custom providers (qwen-local, `auth: none`) that have no auth row.
- Not covered (non-goals): providers configured only through environment API keys (neurastream's env is not omp's), `PI_CODING_AGENT_DIR` (the adapter already assumes ~/.omp/agent, as ompDumpDir does), project-scoped omp configs.

Decisions (challenging Main's sketch):
- One field `unusable: string | null` instead of `configured` + `disabledCause`: the two always move together. `partial` added because cursor's `pool:api` block is real but does not stop every cursor model.
- `providers()` returns `null` for "could not read", not `[]`: with `[]` a schema change would print every provider `gone`. On null main-start prints `unreadable — run neurastream doctor`, the snapshot and provider-out stay untouched, and doctor prints the SQLite error. This is the failure mode for an omp schema change: explicit column names, type-checked fields, any throw → null.
- Feed provider-state, do not replace it: provider-out.jsonl stays the one record every decision reads (cap line, guards, score gate); the harness becomes one more recorder (source `harness`), and only its own records are cleared when omp says ready. Merging the two files would mean rewriting every reader for a different shape. The snapshot file harness-providers.json is new because provider-out holds only out-until records — "new"/"gone"/"unusable" have no place there.
- No spawn refusal: today no guard or cap rule refuses an out provider (the cap prints it; guards.ts:952/:963 only skip it when nudging toward a higher pick), and omp routes around a blocked credential itself. Refusing would be a new policy the owner did not ask for; the feed already makes the existing nudges and the claim guard correct.
- `agent-ledger --cap` re-reads omp before printing, so Main's pre-spawn check is fresh mid-session, not only at start (one line in src/cli/commands.ts; core unchanged).
