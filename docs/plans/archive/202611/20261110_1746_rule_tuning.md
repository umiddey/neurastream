# Rule tuning: the system turns its own noisy rules down and back up

Summary: Noisy detectors and guards step themselves down to log-only or off, one level per UTC day, and a before/after check undoes any demotion that made things worse and holds it for one window — no Main in the loop. Guards sit behind `tuning.guards` (default false) until the owner flips it.

## Goal
- Owner (2026-11-10, shown the sketch, then "plan it"): "Everything already runs without Main: the watch timer fires every 5 min. Today its findings all end in 'open an incident', which needs Main. The sketch changes where they end."
- Done =
  1. A levels file `rule-levels.json` in the queue state dir holds one entry per rule — `block | tell | off`, plus previous level, date, and after an undo `held_until`. Agents already cannot write there (queue state dir is in PROTECTED, src/core/queue/lib.ts:795).
  2. Detector read side: `off` drops a finding, `tell` logs one guard-log line and opens NO incident (incidents are what block Main); the gated detectors and the watcher's own problem kinds both respect it.
  3. A daily tuner step in the watcher: a rule with ≥ `min_fires` fires and < `max_useful` useful share in the window drops one level; one step per UTC day (the levels file's `checked`, stamped by every daily scan, moved or not), one level per step, one notify line per step; a pinned list never drops, and `tuning.keep_off` ids are never probation-raised; a rule that goes quiet steps back up. A rule left at `off` is re-measured: after `probation_days` it steps up to `tell` for one window, then the normal rules judge it again from that window (still noisy: falls back to off; gone quiet: climbs). Usefulness is only observable at `block`, so a `tell` rule is judged by volume alone. A corrupt levels file skips the step and writes no levels file until it is fixed or removed; the step logs one guard_log line per run.
  4. Undo: every level change is judged after its window like a release tag, on the whole-system judgeWindows verdict; each rule-level event's own WORSE verdict restores only that event's rule to its `from` level, and only when that rule's current level still equals `to` and its `held_until` is not in the future; the restored rule is held for `window_days` (the tuner does not move a held rule), and the undo is counted (P5b, narrowed by P10).
  5. The tuner is a row in its own scorecard: more than half its demotions undone in the window → it raises its own bar by the same one-step rule.
  6. "The number" in the weekly report: merged work minus work later flipped bad, per dollar (worker + Main).
  7. Guards: every refusal gets a short stable id, and the same tell/off read side and scoring behind config `tuning.guards`, default false.
  8. Limit (owner): the tuner only turns EXISTING rules down and back up; it never writes a rule, changes code or opens plans (that goes through a plan). Honest name: self-pruning.
