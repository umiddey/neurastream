## Background
Decisions (Main, from the owner's answers; change before spawn if he disagrees):
- **Plans live on the server for team repos.** The server is the source of truth for team plan files, versioned by content sha. A write must name the version it was based on; a stale base → 409, and the client re-reads. Members get a read copy under `<queue_state>/team/<team>/plans/`. Code still moves through the repo's normal MRs, and the server never holds code.
- **Two markers, both needed (owner ~13:20: "we might still wanna not move a team plan to the team queue … we need a marker on top of the label whether it should go to the team queue").** (1) The repo label says a repo MAY share. (2) A plan header line `Queue: team` says this plan DOES share. A plan without it stays personal, even in a team repo, so nothing is shared by accident. `neurastream team share <plan>` adds the line and uploads the plan. `team unshare <plan>` (only while you hold the claim, or the plan is unclaimed) removes it from the server and keeps your local copy. A plan whose repo has no team label is refused by `share`.
- **Repo label = the git remote URL.** The client config has `teams: [{ name, server, repos: ["gitlab.com/aetherios/*", …] }]`. A repo whose `origin` matches no team is personal. The server keeps its own `repos` allow-list and refuses a plan whose remote it does not list. Both sides must agree before anything is stored.
- **Who is who = Tailscale.** The server binds only its tailnet address. Every request is identified by `tailscale whois` of the peer (the src/core/tailscale.ts seam), and that login must be in the server's `members`. There are no passwords and no tokens to leak.
  - A member PC reaches the server either by joining the team tailnet or by having the server node **shared** into their personal tailnet (Tailscale node sharing). With sharing, whois still names the member's login.
  - "Server = team" is the rule. INCIDENT I-20261027-98 (owner ~13:40: "we dont need mypage and teamserver hardcoded like this if we param those"): one command family with a scope flag, no separate `team-server` command. `neurastream ui on --login <l>` = personal page; `neurastream ui on --team <name>` = team page + queue server; `ui off [--team <name>]`; `ui members add|remove|list <login> --team <name>`. Owner ~13:50 picked `workspace`: `neurastream workspace on --login <l>` / `workspace on --team <name>` / `workspace off [--team <name>]` / `workspace members add|remove|list <login> --team <name>`. `--team` refuses to start on a machine where the personal page is on, and the personal page never serves team data.
- **Claims** use the multi_main `ClaimStore` contract, backed by SQLite on the server (one transaction per claim, so it is atomic). The heartbeat every 60 s is an HTTP call, and a claim is free after 30 min without one. If the server is unreachable, the guards refuse spawns on team plans (fail closed), and personal plans keep working.
- **Approvals:** a WAITING line on a team plan is answered by any member, through their own phone page/chat (forwarded) or on the team page. The answer is stored with login + time and shown to everyone.
- **Audit:** every write (plan put, claim, release, approve) goes to an append-only audit log on the server with login + time. Admin = the login that ran `init`. Members are added and removed with `neurastream workspace members add|remove <login> --team <name>`, admin only.

## Forbidden
- Never send a plan, a progress entry, a WAITING line or a file path unless its repo is labelled for that team AND the plan carries `Queue: team`. The check runs in the client before the request, and a fail-before test proves it. The server checks again on its side.
- No auth other than tailnet whois + the member list, and no endpoint without it (health included). Never bind 0.0.0.0. Never shell out with request data.
- Limits: plan ≤ 256 KB, request ≤ 1 MB, 60 writes/min per login (429 above).
- Host-neutral core (docs/adapter.md). Tests inject the Tailscale seam, the clock and a temp SQLite file; they never use the real tailnet or home.
